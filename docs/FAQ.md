# 常见问题与功能边界

## 不用云也能用吗？

可以。Windows EXE 自动启动本机后台，本地短信、电话、卡片和网络功能不需要云账号。公开版云同步默认关闭、地址留空。硬件功能仍要求驱动与模块正常。

## 只复制 EXE 可以吗？

普通用户只需下载一个 `Setup.exe` 并安装，它会自动展开全部组件。不要把安装后的 `DJ4Hub.Windows.exe` 单独复制出去。便携发布目录应完整复制；GitHub 的源码 ZIP 仍需先构建，并非安装包。

## 为什么还有部署说明？安装包不能搞定吗？

安装包已经包括本机程序和后台，本地功能不需要部署。部署说明只给需要手机远程访问、愿意自建云中继的人。安装一个 EXE 不会凭空创建持续在线的公网服务器；公开版也不会连接作者私人云。普通用户保持云同步关闭即可。

## 安装会改驱动、清空数据或要求管理员吗？

默认安装在当前用户目录，不要求管理员；缺少 WebView2 时联网安装 Microsoft 官方组件。不会自动安装未签名硬件驱动，升级与卸载保留用户数据。安装包尚未代码签名；仅从本仓库 Release 下载并对照 SHA-256。正在运行的软件须先从托盘退出再升级。

## 云端是不是与本地完全一模一样？

主要模块管理流程都可远程操作，但原生窗口、自启、系统托盘、驱动安装、Windows 适配器/路由动作和部分本机维护不是浏览器自己的能力。云控制台没有默认 AT 调试入口。远程命令由电脑代执行；主机关闭时不能执行。

## 二块模块都插了，只出现一块？

检查设备管理器是否有两个受支持 AT 端口、USB 供电是否稳定，等待扫描或手动扫描。确认没有旧版本或第三方 AT 工具占用。不要重复装驱动或强杀不明系统进程。

## 第二块 Bark 已经自动绑定了？

首次初始化可能继承本机已有的通知设置，但之后独立。必须选择第二块检查配置并实测一条新短信；上线状态不是通知测试结果。公开版不包含作者推送密钥。

## “AT 接口正在修复 / AT 管理器不可用”？

通常表示通道未就绪或正在重建，先确认 USB/驱动、是否有其他工具占口、是否刚切换 eSIM/模式。短暂等待恢复。持续失败时导出脱敏诊断，说明模块数量、触发步骤和时间；不要上传原始配置或数据库。

## 普通 SIM 显示“未发现 eUICC”？

普通 SIM 不是 eUICC，不应要求它下载 Profile。卡片管理的基础信息与 eSIM 专用操作是不同能力。换兼容 eUICC 卡再测试 eSIM 功能。

## 能把手机当前 eSIM 复制过去吗？

不能承诺。通常不能导出手机安全硬件中的 Profile，需要运营商重新提供支持的激活信息；激活码、卡片实现和绑定策略都会限制下载。

## 可以自动充值保号吗？

不做自动充值。提醒、日期和操作记录是辅助，不代替运营商有效期规则。收短信不一定算有效活动，充值/通话/流量等规则依卡种而异。

## “命令已提交”为什么没有立即变化？

提交只是排队，结果需要主机执行并回传。看最终结果、更新时间、当前设备是否在线；结果不明时先只读确认，尤其不要连续重发短信、下载 Profile 或拨号。

## 云端拨号通了但没有声音？

确认模块 USB 音频、浏览器麦克风、实际选择的输入输出设备以及 TURN/NAT 条件。语音控制与媒体通路是两回事，本项目不能保证所有运营商/固件组合可语音通话。

## Mac 或鸿蒙能直接用这个 EXE 吗？

不能。此发布准备针对 Windows x64；其他平台可以用浏览器访问自己的云控制台，但电脑主机仍需要运行。不随本包提供已验证 macOS/鸿蒙原生客户端。
