# 双模块管理

目标是让两块外观相同的模块可以明确区分、同时工作，避免串台。当前 Windows 分支已做过两块实际模块验证；这不等于对任意数量、型号、USB 集线器作保证。

![双模块架构](images/architecture.png)

## 接入与切换

1. 第一块模块连接后确认正常，给卡片添加自己看得懂的昵称。
2. 插入第二块；正常扫描周期约 30 秒，也可主动重新扫描。
3. 概览显示两个模块卡片，以模块身份和 AT 端口区分，不按插入顺序硬编码。
4. 点击卡片后，“当前控制”选中标记、页面数据、短信、eSIM 与通知设置都应跟随目标模块。

模块身份来自设备 IMEI。换 COM 号不是换模块，拔插后也不应生成另一个陌生控制对象。界面显示短标识帮助区分，但短标识不是匿名化证明。

## 隔离范围

| 项目 | 如何处理 |
| --- | --- |
| 串口 | 每模块绑定自己的 AT 端口；探测和运行主机共用串口所有权互斥机制 |
| 进程 | 每模块一个 Go 后端，拥有不同回环监听端口 |
| 数据 | 主模块保留根目录；其他模块在 `Devices/<模块键>/` 下独立保存 |
| 短信、通话、保号记录 | 不共用单一列表，不在模块之间混合写入 |
| 通知 | 新模块首次初始化可继承通知设置，之后独立保存 |
| 云注册 | 每模块独立注册与主机令牌，不能只打开 A 的同步就认为 B 也绑定了 |
| 故障恢复 | 按模块分别监督、退避重试；不因 A 恢复就主动重启 B |

## 云端也能看到两个模块吗

可以。对 A、B 分别启用同步、使用自己中继的 owner token 注册后，云控制台列出两个设备；每个设备都有独立状态和命令目标。云端选择 B 后，操作不应送到 A。

主机转移配对码只用于已存在云设备的接管，不是新设备首次注册的替代品。

## 供电与争抢

两块模块同时注册/通话时会增加 USB 负载。使用稳定供电，必要时采用可靠有源集线器；故障是否源于供电仍需实际排查，不能凭一条错误信息断定。

本软件避免自己的扫描与主机争抢，但无法禁止外部串口软件占用端口。其他工具正在占用时会报告忙并等待，不强杀进程。不要同时运行旧便携版、另一个 AT 工具或其他同设备管理器。

## 推荐验收

- A/B 分别收到自己手机发送的测试短信，列表不串台。
- 切换 A/B 多次，选中标记与号码/卡片信息同步切换。
- 云端只向目标模块发一条测试命令。
- 暂时拔出 A，B 的状态和读取仍可工作；A 重新插回后按身份恢复。
- 每块模块分别测试 Bark/Telegram，不能只看“在线”标记。

以上短信、通话与切换可能产生费用或影响服务，请使用自己有权操作的卡片。
